# TouchLed169 — повзунок керує яскравістю LED через змінну Code

Плата: **звичайна ESP32 DevKit / ESP32-WROOM-32**, профіль **ESP32 Dev Module** (`esp32:esp32:esp32`). Ця розводка не призначена для ESP32-C3, S3 або плат із вбудованим дисплеєм.

Дисплей: Waveshare **1.69inch Touch LCD Module**, 240×280, ST7789V2 (SPI), тач сімейства CST816 (I²C, адреса `0x15`). У документації виробника зустрічаються позначення S/T/D; конкретний ID вашого екземпляра буде надруковано в Serial. Драйвер слід фізично перевірити саме на вашому модулі.

## Що потрібно

- ESP32 DevKit / WROOM-32 з USB.
- Модуль із фото та його 12-контактний кабель.
- Звичайний малопотужний світлодіод.
- Резистор **330 Ом** (підійде 220–1000 Ом для цього тесту).
- Дроти, за потреби макетна плата.

## Підключення

Від’єднай USB перед підключенням. У таблиці вказані **номери GPIO**, а не порядкові номери контактів гребінки. Орієнтуйся на підписи біля роз’єму модуля; кольори проводів не вгадуємо.

| Контакт дисплея | Контакт ESP32 |
|---|---|
| VCC | **3V3** |
| GND | GND |
| LCD_DIN | GPIO23 |
| LCD_CLK | GPIO18 |
| LCD_CS | GPIO27 |
| LCD_DC | GPIO26 |
| LCD_RST | GPIO25 |
| LCD_BL | GPIO32 |
| TP_SDA | GPIO21 |
| TP_SCL | GPIO22 |
| TP_RST | GPIO33 |
| TP_IRQ | GPIO13 |

Світлодіод: **GPIO14 → резистор 330 Ом → анод LED (+, зазвичай довга ніжка)**. Катод LED (−, зазвичай коротка ніжка / пласка грань корпусу) → **GND**. Земля дисплея, ESP32 та LED спільна. Резистор обов’язковий. Живлення й логічні сигнали модуля у цьому проєкті — 3,3 В, не 5 В.

Якщо на твоїй ESP32 немає будь-якого контакту з таблиці, не підмінюй його схожим номером: спочатку звір модель плати. Усі призначення зібрані в `hardware.h`.

## Запуск і зміна яскравості

1. Відкрий `TouchLed169.ino` у поточному Pinway (`dist/display-code-bindings-ready/Pinway IDE.app`). Вибери ESP32 Dev Module та USB-порт.
2. У Code є одне визначення: `int brightness = 20;`. GPIO14 працює через `ledcAttach(ledPin, 5000, 8)` і `ledcWrite(ledPin, brightness)`.
3. Display автоматично знаходить `brightness` у Code. Вибери її в полі «Прив’язка до змінної» повзунка й тексту. Створювати тестову копію не потрібно. Початкове значення в Display береться з визначення в Code; `const` доступні лише для читання.
4. Повзунок: мінімум0, максимум255, «Активація → Дотик», «Дія → Без додаткової дії». Сам binding записує значення в змінну. Для тексту — binding `brightness`, prefix `Яскравість: `.
5. Натисни Code → «Завантажити». Pinway готує графіку, читання тачу й пряме посилання на C++ змінну автоматично, без ручного експорту.
6. Проведи пальцем по фізичному повзунку. Змінюються `brightness`, число на екрані та PWM яскравість LED. Serial Monitor115200 показує `Pinway: brightness=...`.

Не присвоюй `brightness = 20` на кожному проході loop(), якщо хочеш керувати нею повзунком: такий код перезаписує дотики. Поточний приклад задає20 один раз у визначенні, loop застосовує поточне значення через ledcWrite. Delay1 дозволяє регулярно обробляти дотики.

## Змінні Code та превʼю

Каталог оновлюється з редактора при зміні Code, відкритті Display й перед компіляцією. Підтримуються прості глобальні scalar definitions у головному `.ino` з літеральним початковим значенням: int/float/double/bool та поширені integer types. Коментарі, локальні змінні, масиви, pointers, static/extern, namespaces/classes, складні вирази та умовні `#if` гілки не інтерпретуються як доступні змінні. Видалені/перейменовані bindings позначаються як відсутні.

Локальне превʼю починається зі значення Code і не надсилає команди USB-платі. Фізичний екран після Upload працює з тією самою C++ змінною через generated extern binding. Додаткова ручна тестова змінна потрібна лише для окремої локальної симуляції.

Поточний апаратний adapter підтримує одну числову змінну, touch-повзунки з однаковим цілим діапазоном (до257значень) та текст/індикатор із цією прив’язкою на одній сторінці240×280. Готовий приклад використовує0…255. Не підтримувані дії блокують build із поясненням. Це не повний C++ parser чи універсальний runtime для будь-якого дисплея.

## Графіка та файли

Preview і ESP32 використовують ті самі RGB565 пікселі. Експорт генерує base frame та зміни для кожного значення; ESP32 передає їх смугами по8рядків, без повного framebuffer. Згенеровані `pinway_runtime.cpp`, `pinway_dynamic.h` та setup/loop hooks існують у тимчасовій копії для компіляції. Ручний скетч не переписується при наступних Upload. Збірка через Arduino IDE сама ці прив’язки не додає; для актуального Display використовуй Pinway.

Попередній користувацький скетч і layout збережено в `.pinway/backups/` перед цією інтеграцією. Старі button-driver API залишено для сумісності. У dynamic mode при втраті тачу нових значень не надходить, остання яскравість зберігається; драйвер повторює ініціалізацію.
