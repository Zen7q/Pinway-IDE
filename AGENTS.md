# Pinway IDE — спільний робочий процес

## Git і координація

- Єдина основна гілка проєкту: `main`, remote `origin` — `https://github.com/Zen7q/Pinway-IDE.git`.
- Пряме постійне доручення користувача: після кожного завершеного змістовного етапу перевірити зміни, закомітити всі файли цього етапу й виконати `git push origin main`. Не залишати завершені зміни лише локально. У фінальній відповіді чесно вказувати, якщо push не відбувся.
- Перед роботою перевіряти `git status`, поточну гілку та `git fetch origin`. Узгоджувати паралельну роботу в спільному checkout; не змінювати чужі незавершені правки. Нові довготривалі гілки створювати лише за потреби й узгодженим завданням.
- Зберігати історію: без force-push, reset опублікованої історії чи amend чужих комітів. Контрольний тег `pinway-before-design-rollout-2026-11-22` не змінювати. Оформлення скасовувати точковими revert, див. `UI-DESIGN.md`.
- Комітити код, конфігурацію, потрібні ресурси, тести й документацію. Не публікувати особисті скетчі та робочі макети користувача, секрети, кеші, залежності чи згенеровані збірки. Локальний користувацький `examples/rtt/` не є частиною розробки IDE; зберігати його на диску.

## Якість інтерфейсу

- Display — еталон спільного оформлення Code/Build/Display: узгоджувати композицію, панелі, типографіку, відступи та стани. Ширина лівої панелі спільна для всіх вкладок.
- Завжди перевіряти input/select та інші форми: висоти, відступи, рамки, стрілки, читабельність, focus/hover/disabled, обидві теми й вузькі вікна. Для UI-змін перевіряти реальний macOS WebKit застосунок.
- Не змінювати користувацькі скетчі/макети й не прошивати плату лише заради UI-перевірки. Нові збірки створювати в окремих папках, попередні збережені app не перезаписувати.
